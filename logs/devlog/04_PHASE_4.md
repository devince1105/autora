## T-402（重做）· 依參考圖改成等角剖面辦公室（D-010，2026-09-19）

使用者提供四張參考圖（等角剖面辦公室：白色牆頂、黃色走道、深色工作區、長條桌雙螢幕、玻璃隔間、會議室、茶水間、休息區、大量植物、柔和陰影），指出第一版與理想差太多。參考圖是商用素材包的渲染圖，**只參考風格，不使用其素材**，記為 D-010。

### 做了什麼
- **佈局重畫**（`layout.ts`，24 × 16 公尺）：後排由左到右是執行長玻璃辦公室（木地板、書櫃、沙發、門）、會議室（玻璃隔間、長桌 8 椅、投影幕、白板）、茶水間（櫥櫃、冰箱、販賣機、飲水機、吧台桌）；中間是兩條黃色走道夾著深色工作區，研究與編輯兩張長條桌各 4 個座位；前排是行銷 3 張、空桌 3 張、審批桌（櫃台造型、黃色飾條）與休息區（粉紅地毯、沙發、單人椅、茶几）。座位、容量、分配規則與交接路線的規則不變。
- **程式產生的模型**（`scene/kit.ts`、`scene/furniture.ts`）：辦公椅（五爪腳、彩色條紋依角色）、長條桌與黑色桌腳、雙螢幕與鍵盤、書架與書、棕櫚與盆栽、沙發、會議桌、茶水間設備、窗戶、畫框、玻璃隔間的白框與黃色門。全部**合併成一個頂點色網格**，所以細節再多也只一次繪製。裝飾品也寫在 `layout.ts` 的 `DECOR`，走路測試一併避開。
- **地板**（`Floors.tsx`、`textures.ts`）：淺灰底、深色亮面工作區、黃色走道、程式繪製的木地板與磁磚、地毯。
- **畫面**：正交等角相機 + `Bounds` 自動對齊、藍灰漸層背景、Neutral 色調映射、左上方主光投射陰影、`Lightformer` 環境光。
- 螢幕（每座位兩個）改為 `<Instances>`，T-406 依代理狀態點亮。

### 過程中的問題（都在截圖中發現）
- **陰影完全看不到**：先以為是陰影沒開，把渲染器狀態讀出來確認陰影貼圖、光源、投影物件都正常；真正原因是主光和鏡頭在同一側，影子全落在物體背後。主光改從左上方來之後陰影就出現，但後牆與左牆內側變暗，再用兩片側向的 `Lightformer` 補光。
- 棕櫚葉太細、從這個角度看像棍子 → 葉片加寬、下垂。編輯長條桌右端的高書櫃背對鏡頭，看起來像一塊黑色石碑 → 改為盆栽。
- 環境光太強時地板過曝、陰影被洗掉 → 降低環境與半球光、提高主光。
- 開發伺服器在我刪除 / 改名檔案後出現 Turbopack 內部的 HMR 錯誤（快取指向已不存在的模組），重啟後正常。

### 驗證

## T-402 · 辦公室佈局、房間與工作區

### 做了什麼
- `office3d/scene/layout.ts`：**唯一的座標來源**（04 §2）。依角色（不是代理）排座位：
  - 工作排（z=0）由左到右：研究員、分析師、寫手、編輯，每個角色 2 張桌；前排（z=4.5）：行銷 3 張、給未知角色的空桌 3 張、審批桌；後方玻璃隔間是執行長辦公室（有門），右後方是會議桌（裝飾）。
  - `seatsForRole(role, n)`（最多到該區容量）、`assignSeats(agents)`（同角色依代理 id 排，結果穩定；未知角色用空桌；坐不下的列在 `unseated`，只出現在 2D 看板與清單）。
  - `walkPath(from, to)`：交接路線（T-408 用）——起身 → 走到座位旁 → 走道（前 / 後兩條）→ 必要時經中央走道換走道 → 目標座位旁；執行長辦公室從門進出。回程把路線反過來走。
- 場景：`Room`（地板、後牆與左牆、窗戶、執行長玻璃隔間、會議桌、審批桌、盆栽）、`Zones`（每區一塊粉彩地毯）、`Furniture`（桌面、桌腳、椅面、椅背、椅柱、螢幕、螢幕面板，**全部用 drei `<Instances>`，每種零件一次繪製**）、`OfficeScene` 組裝。螢幕目前是暗的，T-406 依代理狀態點亮。
- 色調：R3F 預設的 ACES 色調映射會把粉彩壓灰，改用 `flat`（照調色盤原色）並調亮環境光（D-008 的明亮粉彩）。
- `perf/StatsProbe`：畫布內每秒記錄一次 FPS、繪製呼叫數、三角形數到 `window.__autoraOffice`，瀏覽器測試用來斷言，T-412 長時間測試也會用。

- 原本訪客站在座位後方，前排的路線會穿過桌子（手算時發現），改成站在座位右側（或左側）。
- 瀏覽器測試兩個時機問題（先前碰巧通過）：畫布在量到容器大小前是預設的 300 px 寬，改為等待；context 遺失的測試在場景完成設定前就觸發，改為等場景開始繪製後再觸發。

## T-401 · OfficeCanvas

### 做了什麼
- 新頁面 **`/office`**（Dashboard 右上角「辦公室」連結）：標頭有「自動 / 3D / 2D」切換（寫在網址 `?view=3d|2d`，可分享）、Dashboard 連結、連線狀態；下方是辦公室畫布。
- `office3d/OfficeCanvas.tsx`（3D 層唯一對外的元件，ESLint 規則已限制）：
  - **選擇 3D 或 2D**（`capabilities.ts`，純函式）：沒有 WebGL 2 一律 2D（就算選了 3D）；窄螢幕（≤ 768 px）自動用 2D，但可手動切到 3D；偵測用的 WebGL context 用完立即釋放。只在瀏覽器端偵測一次，伺服器端渲染時先顯示空白區。
  - **動態載入**：WebGL 部分（`Canvas3D.tsx`）用 `next/dynamic`（`ssr: false`）只在選了 3D 時才下載。
  - **DPR** `[1, 1.5]`；**分頁隱藏時停止繪製**（`frameloop="never"`）。
  - **WebGL context 遺失**：顯示「3D 暫停」與「重新建立 3D」「改用 2D 看板」兩個按鈕；**不自動重試**。重新建立 = 換一個新的畫布（新的 context）；瀏覽器自己恢復 context 時提示自動消失。
- `Canvas3D.tsx` 目前只有相機、燈光與地板（暖色粉彩，D-008）；房間、桌椅與人物從 T-402 開始。
- `fallback/OfficeBoard2D.tsx`：暫時的 2D 看板，列出代理的名字、角色、狀態；T-410 再依視覺對照表做完整版。

### 決策：React 釘在 19.2.8（D-009）
安裝 React Three Fiber 9.7（最新穩定版）時出現 peer 警告：它只支援 `react <19.3`，並內建對應 React 19.2 的 reconciler，而專案原本用 19.3.0。錯配是未經測試的組合，所以改用 19.2.8（同一大版本內的小降版，Next 16.3.5 支援），等 R3F 支援 19.3 再升級。改版後原有全部測試與階段 3 的兩個驗收測試都通過。

### 過程中的問題
- 安裝套件時 pnpm 重整 `node_modules`，開著的開發伺服器（3000）因此找不到套件、出現一連串錯誤；重啟開發伺服器後恢復正常。**之後安裝套件要順手重啟開發伺服器。**
- Playwright 的 CSS 選擇器 `[data-office-mode=3d]` 不合法（屬性值以數字開頭必須加引號）；Next 的路由播報器也是 `role="alert"`，測試改以文字找「3D 暫停」提示。

### 驗證
- `office-canvas.test.tsx`：13 個通過——3D / 2D 選擇的完整對照、`?view=` 解析、WebGL 2 偵測（含釋放偵測用 context、偵測拋錯）、無 WebGL 顯示 2D 與原因、窄螢幕、分頁隱藏停止繪製、context 遺失的提示與**只在按下按鈕時重建**、瀏覽器自行恢復。
- **真實瀏覽器**（`e2e/office.spec.ts`，Playwright + 測試環境，本機 Chrome）：3 個通過——桌機得到 WebGL 2 畫布且 context 正常；用 `WEBGL_lose_context` 真的讓 context 遺失 → 出現提示 → 按「重新建立 3D」得到新的可用 context；`?view=2d`、手機寬度（390 px）、停用 WebGL 2 的瀏覽器都顯示 2D 看板（列出 3 位代理）。我看過截圖：3D 畫面有打光的地板與暖色背景，連線狀態「即時」。
- CI 的 Linux 環境沒有 GPU：Playwright 在 CI 加上 SwiftShader 參數（軟體 WebGL）。
- web 共 110 個測試、event-schema 8 個通過；`typecheck`、`lint`、`next build`（新路由 `/office`）、`gen-api:check` 以結束碼確認通過；`make e2e` 5 個（辦公室 3 個 + 階段 3 驗收 2 個）通過。
- 開發伺服器重啟後 `/office` 編譯無錯誤、主控台無錯誤（停在權杖畫面）。
